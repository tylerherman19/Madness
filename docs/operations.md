# MADNESS deployment checks

- Set `NEXT_PUBLIC_APP_URL` to the primary HTTPS domain before building. Metadata, canonicals and sitemap entries use that origin (default: `https://madness-cyan.vercel.app`). Redirect alternate production domains to that primary domain in Vercel to avoid duplicate content.
- `NEXT_PUBLIC_SUPPORT_EMAIL` can override the existing `pool@pickandpray.org` contact. Confirm it reaches the organizer. Fee/payment copy follows the current $25 / @griffinsell pool. Confirm and update refund/payout details before accepting payments if the organizer has different policies.
- Enable Web Analytics in the Vercel project dashboard. The integration is installed, uses no analytics cookies, excludes account/admin/API pages, and strips query strings and fragments. This repository has no advertising trackers; adding tracking that requires consent also requires a consent flow and a privacy-policy update.
- Vercel enforces HTTPS for hosted deployments; the app adds HSTS and upgrades insecure subresources in production. CSP allows inline scripts required by Next.js hydration and inline styles used by the existing UI. Production excludes `unsafe-eval`. A stricter nonce policy would require converting the existing static/ISR pages to per-request rendering.
- Monitor `GET /api/health` from an external uptime service. A 200 means the server and a read-only database query succeeded; 503 means database access/configuration failed or timed out. No monitoring account or alert destination is provisioned by this code. Vercel runtime logs retain server errors; error screens let players retry or reach the organizer.
- Existing authenticated exports: `/api/admin/export?type=players` and `/api/admin/export?type=picks`, accessible from the admin UI. They are CSV exports, not full restorable backups. Use Supabase backups/point-in-time recovery according to the project plan; download a verified database backup before destructive operations. Store exports securely because they contain personal information. No automated backup service is provisioned by this change.
- All API mutations pass an IP-based 120/minute limiter and reject mismatched browser Origins. Login, signup and reset routes retain tighter budgets. Supabase's atomic limiter shares counts across instances; an outage falls back to bounded process-local budgets, which cannot share limits across instances.
- Validate with `npm ci`, `npm test`, `npm run lint`, `npm run build`, then `npm start`. Check the legal pages, signup consent, mobile navigation/footer, social image, sitemap, robots, and a nonexistent route. Use a physical phone for a final device check; browser emulation is not a physical device test.
